# 音源について

## 現在入っている音源

| ファイル | 用途 | 鳴るタイミング | ループ長 | 実測 |
|---|---|---|---|---|
| `bgm1.mp3` | 持ち込み曲 | 両者とも4000以上 | 6.4015秒 | RMS 0.170 / ピーク 0.762 |
| `bgm2.mp3` | 持ち込み曲 | どちらかが3999以下 | 12.7801秒 | RMS 0.189 / ピーク 0.785 |
| `bgm3.mp3` | 持ち込み曲 | どちらかが1999以下 | 12.8456秒 | RMS 0.176 / ピーク 0.742 |
| `bgm4.mp3` | 持ち込み曲 | **お互い3999以下（最優先）** | 12.7709秒 | RMS 0.195 / ピーク 0.846 |
| `damage.m4a` | 減少音（ピロピロピロ…ピコン） | ライフが減った時（`−` と `÷2`） | 1.1秒 | 合成音 |
| **`buzzer.m4a`** | **決着のブザー「ビーーー」** | **どちらかのライフが0になった時** | 2.2秒 | 合成音 |
| `coin.m4a` | コイントス | アクセサリのコイン | 1.0秒 | 合成音 |
| `dice.m4a` | サイコロ | アクセサリのダイス | 1.2秒 | 合成音 |

**BGM1〜4はすべて持ち込みのmp3**（48kHz・ステレオ、合計約820KB）。`index.html` の `AUDIO_CFG` に
正確なループ長を書いてあります。**4曲とも音量が揃っていて（RMS 0.17〜0.19）クリップも無かったので、
音量補正（gain）は入れていません。**

## 決着時の動作

**どちらかのライフが0になると、ブザー「ビーーー」が鳴ってBGMが止まります**（0.25秒でフェードアウト）。
画面表示は変わらず、そのまま操作も続けられます。

- ブザーは減少音とは別枠なので、被弾音とブザーが重なって聞こえます
- **ライフが0より上に戻ると（Undo・加算・リセット）ブザーが止まり、その時点のBGMが再開します**
- ブザーは合成音です（`tools-synth.py` の `buzzer()`）。220Hzの矩形波を±5セントでデチューンし、
  上下のオクターブを重ねて語尾のピッチを落としています。差し替えたい場合は `buzzer.mp3` を置けばOK

## 合成音について

減少音・ブザー・コイン・ダイスは、コードで合成したオリジナルの音です。
遊戯王やその他の既存楽曲は一切使用・複製していません。

音作りの構成（合成音）：
- リードは**±8〜11セントにデチューンした2声を左右に配置**（太さと広がり）＋PWMで音色を揺らす
- ベースは矩形波に**1オクターブ下のサイン波（サブ）を重ねて**低域を補強
- **ピンポンディレイ**（付点8分・4分）と短いルームリバーブで奥行き
- ドラムはレイヤー：キック（本体＋サブ＋クリック）、スネア（明るい層＋胴鳴り＋ピッチ落ちトーン）、
  左右に振ったハット、8小節ごとのクラッシュ、8小節目のタムフィル
- BGM1にはコードスタブを追加

合成したBGMの仮音源（`bgm1〜4.m4a`）は持ち込み曲に置き換わったため削除しました。
必要なら git 履歴から戻せます（`tools-synth.py` で作り直すこともできます）。

## ループの継ぎ目について（差し替える人向け）

再生は **Web Audio API** で行っています。`<audio loop>` はループ位置がサンプル単位で正確でなく
継ぎ目に隙間ができるため、デコード済みバッファをループさせる方式にしてあります。

同梱の `.m4a` はさらに一段の対策をしています。**ループ本体の後ろに「先頭0.5秒ぶんのコピー」を余白として
付けて書き出し、アプリ側は `index.html` の `LOOP_SEC` に書かれた正確な尺でループ終端を指定**しています。
AACやmp3はデコード時に末尾が数十ms削れることがあり、余白が無いとその分だけループが短くなって
リズムが詰まるためです。

**自分で `.mp3` を置いた場合**は `LOOP_SEC` を使わず、末尾の無音を自動で削った位置でループします。
それでも継ぎ目が気になるときは、ループ本体の後ろに先頭のコピーを0.5秒ほど足した音源を作り、
`index.html` の `LOOP_SEC` にそのトラックの正確なループ長（秒）を書き足してください。

## 差し替え方

**同じ名前で置くだけです。** アプリは各トラックについて **`.mp3` → `.m4a` → `.ogg` → `.wav`** の順に探し、
先に見つかったものを使うので、`bgm1.mp3` を置けば同梱の `bgm1.m4a` より優先されます。
`.m4a` の方を消す必要はありません（消しても構いません）。

```
assets/audio/bgm1.mp3   ← これを置けば bgm1.m4a より優先される
```

- 差し替えたいトラックだけ置けばOK。置かなかったものは同梱の仮音源のままです。
- **どれも無いトラックは単に鳴りません**（エラーにはならず、無音のまま動作します）。
- **BGMはループ再生されます。** 切替時は300msのクロスフェードがかかります。
- **同じファイル名で中身だけ差し替えた場合、反映されるのは次の起動からです。**
  Service Workerがキャッシュを即座に返しつつ裏で更新を取りに行くため、
  1回目の起動は古い音、2回目から新しい音になります（`sw.js` の `CACHE` の数字を
  上げれば1回目から反映されます）。**別のファイル名で置いた場合は最初から新しい音です**
  （例：`bgm2.m4a` を残したまま `bgm2.mp3` を追加 → mp3が優先されて即反映）。
- **遊戯王の公式音源（アニメ・ゲームのBGM）は著作権上使用できません。** フリー素材（DOVA-SYNDROME、効果音ラボ など、各サイトの利用規約を確認のうえ）または自作音源を使ってください。

## 自作曲を入れるとき

`index.html` の冒頭にある `AUDIO_CFG` に、その曲のループ位置と音量を書けます。
**ここに書かない場合は「前後の無音を自動で削った範囲」をループします**（手軽ですが、
リバーブの余韻が削れたり、サンプル単位ではズレたりします）。

```js
var AUDIO_CFG = {
  // 実際に入っている設定（持ち込みmp3は先頭から丸ごと1ループ）
  bgm3:{ forExt:'mp3', loopStart:0, loopEnd:97.700000, gain:0.49 },
  bgm4:{ forExt:'mp3', loopStart:0, loopEnd:94.462063, gain:0.45 },
  // イントロ4秒 → 92秒のループ本体、という曲ならこう書く
  // bgm3:{ forExt:'*', loopStart:4.0, loopEnd:96.0, gain:0.8 },
};
```

`loopEnd` の正確な値は macOS なら `afinfo ファイル名.mp3` で出る
`valid frames` をサンプリングレートで割ると求まります（例：`4165777 / 44100 = 94.462063`）。

| 項目 | 意味 |
|---|---|
| `loopStart` / `loopEnd` | ループ区間（秒・ファイル先頭からの絶対時間）。イントロ付きの曲も作れます |
| `gain` | そのトラックだけの音量補正（1.0＝そのまま）。曲ごとの音量差を揃えるのに使います |
| `forExt` | この値が有効な拡張子。`'*'` ならどの拡張子でも適用。同梱音源用の値には `'m4a'` が入っています |

**継ぎ目を完全に無くしたいときは、書き出しの時点でループ本体の後ろに「先頭0.5秒ぶんのコピー」を足してください。**
mp3やAACはデコード時に末尾が数十ms削られることがあり、余白があるとその影響を受けません。
同梱音源はこの方式で作っています（`tools-synth.py` の `with_tail()`）。

### 曲の長さについて

再生前にデコードするため、**長い曲ほどメモリを使います**（デコード後はfloat32になり、
ステレオ1分あたり約21MB）。アプリは曲の長さで挙動を変えます。

| 曲の長さ | 挙動 |
|---|---|
| 45秒以下 | 4曲すべてを起動時にデコードして保持。切替は即座 |
| 45秒超 | 必要になった時にデコードし、**同時に持つのは2曲まで**。古いものからメモリを解放 |

長い曲の場合、まだデコードできていないBGMに切り替わる瞬間は**今のBGMを鳴らしたまま待ち、
用意でき次第クロスフェード**します（無音にはなりません）。デコードは26秒の曲で約35ms、
3分の曲だとPCで0.3秒前後・スマホで1秒前後が目安です。

**推奨は90秒以内のループ**です。3分を超える曲を4本入れると、メモリのピークが
120MBを超えて古いスマホでは苦しくなります。その場合はループを短く切り出すか、
ビットレートを下げてください。

なお、Service Worker がインストール時に先読みするのは **アプリ本体＋効果音だけ**です。
BGMはアプリが取得と同時に自分でキャッシュへ入れるので、長い曲に差し替えても初回の
インストールが重くならず、それでいて初回アクセスだけでオフライン対応になります。

## 自分で差し替えるときの手順（まとめ）

1. `assets/audio/` に `bgm2.mp3` のように置く（`.mp3` は同名の `.m4a` より優先される）
2. ループを正確にしたい・音量を揃えたいなら、`index.html` の `AUDIO_CFG` に
   `loopStart` / `loopEnd` / `gain` を書く。書かなければ自動処理される
3. コミットして push（GitHub Pages が1〜3分で反映）
4. スマホで開く。**同じファイル名で差し替えた場合だけ、2回目の起動から反映される**

ループ長と音量の測り方が分からない場合は、ブラウザの開発者コンソールで次を実行すると出ます。

```js
Object.entries(__ygo.audio.bufs).forEach(([k,b])=>{
  const d=b.buffer.getChannelData(0); let s=0;
  for(let i=0;i<d.length;i+=7) s+=d[i]*d[i];
  console.log(k,'秒:',b.buffer.duration.toFixed(3),'RMS:',Math.sqrt(s/(d.length/7)).toFixed(3));
});
```


## 知っておくこと

- ブラウザの仕様上、**ページを開いた直後は音が鳴りません。** 画面のどこかを最初にタップした時点で音声が有効になります
  （それまでヘッダーに「🔇 タップで音声ON」と表示されます）。
- 音量はアプリの設定画面（⚙）で BGM / 効果音 それぞれ調整できます。ヘッダーの 🔊 ボタンで一括ミュートもできます。
- 音源を入れ替えても反映されない場合は、Service Worker が古いファイルをキャッシュしています。
  `sw.js` 冒頭の `var CACHE = 'ygolife-v1';` の数字を上げて再デプロイしてください。
